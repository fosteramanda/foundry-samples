# Coding Agent Instructions — Voice Live Bridge Basic .NET

This is a Microsoft Foundry hosted text agent that implements Voice Live Bridge Protocol `1.0`
over `invocations_ws`. Voice Live owns the audio pipeline; this sample handles only typed text and
control events.

## Deployment mode

- Direct code deployment: `azure.yaml` declares .NET 10 and `VoiceLiveBridgeBasic.dll` as the entry
  point.
- Keep the sample self-contained under this directory. Do not add Docker artifacts, sibling-path
  dependencies, local packages, private feeds, or generated `.vscode` files.

## Key files

- `azure.yaml` — Foundry project, model, hosted-agent metadata, and protocol declaration
- `src/voice-live-bridge-basic-dotnet/Program.cs` — server entry point and dependency registration
- `src/voice-live-bridge-basic-dotnet/VoiceAgent.cs` — thin Bridge callback and command handler
- `src/voice-live-bridge-basic-dotnet/VoiceConnectionState.cs` — per-connection admission and lifecycle state
- `src/voice-live-bridge-basic-dotnet/ConversationHistory.cs` — bounded history and barge-in reconciliation stores
- `src/voice-live-bridge-basic-dotnet/VoiceResponseCoordinator.cs` — response execution, wire sequencing, and cleanup
- `src/voice-live-bridge-basic-dotnet/AzureOpenAIResponsesClient.cs` — Foundry Responses adapter
- `src/voice-live-bridge-basic-dotnet/tests/` — deterministic unit tests and test doubles
- `src/voice-live-bridge-basic-dotnet/smoke/` — protocol-aware WebSocket smoke client
- `sample.yaml` — repository build-readiness validation

Do not commit `.vscode` launch or task files generated by the Foundry Toolkit.

## Dependencies and feeds

- Keep direct package versions explicit in each project file.
- `Azure.AI.AgentServer.*` resolves only from the public `azure-sdk-for-net` feed configured in
  `NuGet.config`; all other packages resolve from NuGet.org through package source mapping.
- Do not add credentials, local NuGet packages, VCS dependencies, or private feeds.

## Runtime logging

Use `ILogger` for server diagnostics. Reserve `Console.WriteLine` for the smoke client, where stdout
is the intended interface. Never log prompts, responses, credentials, API keys, or bearer tokens.

## Development workflow

From an initialized agent project, use `azd provision`, `azd ai agent run`, and `azd deploy` for the
hosted-agent lifecycle. Do not use `azd ai agent invoke` or Agent Inspector as protocol tests because
they do not produce Voice Live Bridge WebSocket events; run the smoke client instead.

Restore, build, format, and test from the sample root using the commands in `sample.yaml`.

## Protocol constraints

- Keep `bridgeProtocolVersion: "1.0"`, `voiceLiveCompatible: "true"`, and `invocations_ws` version
  `2.0.0` aligned with the manifest.
- Bridge Protocol `1.0` is the application protocol; `invocations_ws` `2.0.0` is the Hosted Agent
  ingress transport version. Do not conflate them.
- The application explicitly sends `session.ready` or `session.rejected` and owns response IDs,
  background tasks, cancellation, and conversation state.
- Protocol `1.0` supports text input only. Do not add DTMF, image input, history mutation, or
  hosted-agent handoff under this version.
